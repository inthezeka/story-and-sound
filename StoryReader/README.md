# Story & Sound — Content Studio Edition

소설을 넘기며 챕터·장면에 맞춰 배경음악과 이미지가 바뀌는 모바일/PC 웹소설 뷰어입니다. **이번 버전은 관리자 편집 화면을 추가**했습니다. HTML/CSS/JavaScript는 `index.html` 단일 파일에 포함되어 있으며 별도 빌드나 계정 가입이 필요하지 않습니다.

## 1. 바로 실행

1. `StoryReader/` 폴더를 압축 해제합니다.
2. `index.html`을 열면 표지 화면이 나타납니다. `이야기 시작하기`(음악 ON) 또는 `음악 없이 시작하기`를 선택합니다.
3. **관리자 모드**: 표지의 **「✦ 관리자 · 소설과 음악 편집」** 버튼, 또는 독서 화면의 **「설정 → 관리자 모드 열기」**를 클릭합니다.
4. 관리 화면에서 챕터를 선택해 원고·BGM·이미지를 편집하고 **변경 내용 저장**을 누릅니다.

**중요:** `file://`로 직접 열 때 일부 브라우저(특히 Safari)의 보안 정책 때문에 IndexedDB가 제한될 수 있습니다. 브라우저 편집 내용이 저장되지 않는 경우 `StoryReader` 폴더에서 `python -m http.server 8000` 명령을 실행하고 `http://localhost:8000`으로 접속하세요. GitHub Pages에서는 별도 서버 작업 없이 편집할 수 있습니다. 다만 편집한 내용의 온라인 **게시**는 별개입니다.

## 2. TXT 소설 원고 불러오기

- Content Studio → 챕터 선택 → **「TXT 원고 불러오기」**에서 UTF-8 `.txt` 파일 선택
- 텍스트는 관리자 원고 입력창에서 직접 수정할 수 있습니다.
- **빈 줄**로 문단을 구분합니다. `---`만 있는 한 줄은 화면상의 `· · ·` 구분선으로 처리됩니다.
- 장면별 전환은 아래 **장면별 연출 / Scene Timeline**에서 설정합니다.
- TXT 파일을 다시 불러오거나 문단을 크게 변경하면 장면 시작 문단을 재확인하세요.

## 3. 챕터별 음악과 배경 이미지

- Content Studio → 챕터 선택 → 기본 BGM의 **「MP3 업로드」**에서 MP3 선택
- **곡 제목**을 입력하거나 자동으로 제안된 파일명을 사용합니다.
- 기본 배경의 **「이미지 업로드」**에서 JPG/PNG/WEBP/GIF 선택
- 업로드 파일은 브라우저의 IndexedDB에 Blob 형태로 저장됩니다. `localStorage`에 대용량 MP3를 저장하지 않습니다.
- 음악은 페이지를 넘기는 중 끊기지 않고, 음원 파일을 교체할 때 기존 2중 플레이어가 크로스페이드를 시도합니다.
- 개별 업로드 파일 크기는 **45MB 이하**입니다. 여러 음원의 총합 용량은 브라우저 저장 할당량에 영향을 받습니다.

## 4. 장면 전환 음악/BGM과 배경

1. 소설 원고를 입력합니다.
2. **「장면 전환 추가」**를 누릅니다.
3. **「전환 시작 문단」**에서 해당 음악/배경이 시작될 문단을 지정합니다.
4. 각 장면의 **「MP3 선택」**, **「이미지 선택」**으로 파일을 업로드합니다.
5. 원하는 수의 장면을 추가한 뒤 **변경 내용 저장**을 누릅니다.

장면은 앞의 설정을 상속합니다. 특정 장면에서 배경/음악을 비워두면 기존에 재생 중이던 설정이 계속 유지됩니다. 중단이 필요하면 챕터 BGM 자체를 해제하거나 음소거 버튼을 사용하세요.

## 5. 챕터 추가 / 정렬 / 삭제

- 왼쪽(스마트폰은 위쪽) 챕터 목록에서 **「+ 새 챕터」**를 선택하면 새로운 챕터를 만들 수 있습니다.
- 제목·목차 설명·본문·음악·이미지·장면 설정을 개별 관리합니다.
- **↑ 순서 올리기 / ↓ 순서 내리기 / 챕터 삭제**를 지원합니다.
- 챕터 개수에 따라 목차와 페이지 목록이 자동으로 갱신됩니다. 예제 챕터 3개가 기본 포함되어 있으며 10개 이상 확장 가능합니다.

## 6. GitHub Pages에 편집 내용을 실제로 게시하기 (핵심)

> **관리자 모드는 비밀번호 기반 서버 관리자가 아닙니다.** 직접 편집한 내용은 **현재 브라우저에만 저장**되므로, 단순히 「변경 내용 저장」을 누른 것만으로 방문자에게 공개되지는 않습니다.

1. Content Studio → **「배포 · 백업」** 탭으로 이동합니다.
2. **「게시 및 백업용 content.json 다운로드」**를 누릅니다.
3. 다운로드된 파일을 GitHub 저장소의 **`index.html`과 같은 폴더**에 `content.json`으로 업로드합니다 (기존 파일은 교체).
4. GitHub 저장소 `Settings → Pages → Build and deployment → Deploy from a branch → main / (root)`를 지정합니다.
5. 배포가 끝나면 휴대폰 등 다른 기기에서 사이트를 새로고침하여 반영을 확인합니다.

`content.json`에는 스토리 JSON과 업로드한 음원/이미지가 **Base64 데이터**로 함께 포함됩니다. 이 파일 한 개만 갱신하면 새로 업로드한 파일까지 독자에게 전달됩니다. 하지만 45MB MP3 2곡은 JSON 용량이 약 120MB가 될 수 있습니다. GitHub 파일 크기 제한에 걸릴 수 있으므로, 실제 작품을 게시할 때는 음원 파일을 용량 적게 압축하거나 `music/` 폴더에 원본을 직접 올리는 것을 권장합니다.

**Github Pages 기본 배포 구조**

```
repository-root/
  index.html        # 뷰어 + Content Studio 코드
  content.json      # 관리자 내보내기 결과물 (추가 업로드)
  music/            # 기존 샘플 MP3 5곡
  images/           # 기존 표지/배경 이미지 4장
```

일반 독자는 URL을 열면 먼저 `content.json`이 있으면 해당 공개 원고를 읽습니다. **로컬 관리자 초안**이 남아 있는 현재 브라우저에서는 그 초안이 우선 표시되므로, 공개 상태 검증은 새 브라우저/시크릿 창/다른 기기에서 하세요.

## 7. 원고 백업 및 다른 기기에서 수정

- **배포 · 백업 → content.json 다운로드** = 완전 백업(원고, 음악 파일, 이미지 파일 포함)
- 새 PC나 브라우저에서 **「content.json 가져오기」** = 챕터, 장면, 음원, 이미지 모두 로컬 편집 가능 상태로 복원
- **「이 브라우저 초안 초기화」** = 브라우저 초안과 로컬 파일을 지우고 공개 버전(없으면 샘플)으로 복귀
- 기존 `music/*.mp3`, `images/*.jpg` 예제 파일도 그대로 유지됩니다.

## 8. 원래 독서 뷰어의 기능

- 스마트폰: 왼쪽 스와이프 → 다음 페이지, 오른쪽 스와이프 → 이전 페이지, 화면 양측 탭
- PC: 클릭, 마우스 드래그, 방향키, Space
- 문단 우선 / 실제 높이 측정에 따른 반응형 자동 페이지 분할
- 챕터별 BGM 및 장면별 전환, 크로스페이드, 음악 재생·일시정지·볼륨·음소거
- Light / Sepia / Dark / Cinematic, 글꼴·글자 크기·줄 간격·여백 설정
- 읽던 위치와 환경 설정 자동 저장, PC 양면 보기, 전체 화면, 모션 감소 설정

## 9. 보안 및 개인정보

- 사이트에 로그인이나 서버 관리자 인증은 없습니다. **관리자 편집 화면은 누구나 열 수 있지만 자신이 편집한 브라우저 내 데이터만 바뀝니다.**
- 공개 사이트의 실제 콘텐츠 수정은 GitHub 저장소에 업로드할 권한이 있는 사람만 할 수 있습니다.
- 로컬 독서 위치, 설정, 원고 초안과 업로드 음원/이미지는 외부 서버로 자동 전송하지 않습니다.
- `content.json`을 GitHub에 게시하는 순간 그 안의 원고·미디어는 공개적으로 전달되고 다운로드될 수 있으니 저작권을 확인하세요.
- 브라우저 캐시/사이트 데이터 삭제 시 로컬 초안도 사라질 수 있습니다. 자주 백업하세요.

## 10. 알려진 브라우저 제약

- 브라우저의 자동재생 정책으로 인해 페이지 이동에 맞춘 음악 변경 시 모바일 Safari 등에서 재생 버튼의 추가 탭이 필요할 수 있습니다.
- 저사양 스마트폰에서는 고해상도 배경과 큰 MP3 파일의 로딩 지연이 발생할 수 있습니다.
- `content.json`은 JSON 단일 파일 배포 방식이므로 대형 작품에서는 파일이 커질 수 있으며 전용 서버/스토리 CMS보다 효율적이지 않습니다.
- 브라우저 자동화 환경에서 차단이 발생하여 실제 모바일 Safari와 Android 기기까지 검증하지는 못했습니다.
